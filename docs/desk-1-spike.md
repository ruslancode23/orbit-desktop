# DESK-1 — spike оболочки: таблица «работает / нет»

Прогон 27.10.2026 на macOS. Windows в этой проверке нет: по принятому решению от 27.10.2026 его
сборка идёт только в GitHub Actions, а полная проверка голоса и экрана — после стенда с HTTPS (REL-3).

Легенда: ✅ работает · ⚠️ проверено косвенно (API есть, сценарий руками не прогнан) · ⬜ не проверено.

## Как прогнать

```bash
cd ../orbit-web && pnpm dev                       # 1. приложение
cd ../orbit-server && make up && make run          # 2. API (нужен для входа)
cd ../orbit-desktop
ORBIT_DESKTOP_PROBE=1 pnpm dev                     # 3. оболочка + проба
```

`ORBIT_DESKTOP_PROBE=1` (только debug) вставляет JS после загрузки страницы и печатает в stdout одну
строку `[probe] {…}`. Сырой результат этого прогона — [evidence/probe-macos-2026-10-27.json](evidence/probe-macos-2026-10-27.json).
Без переменной проба не запускается; в release-сборке команды `report_spike` нет вовсе.

## Что это значит

1. **Вариант A (ADR-0006) подтверждён.** Сессия в оболочке живёт на той же cookie, что и в браузере,
   и никаких правок сервера для этого не понадобилось. Проверка шла даже в более строгом режиме, чем
   прод: `localhost:5173` → `localhost:8080` — это cross-origin (в проде будет same-origin).
2. **Единственный открытый риск DESK-1 — демонстрация экрана.** API в WKWebView есть, но работает ли
   реальный захват, решает TCC и версия macOS. Это проверяется только руками, с человеком у экрана:
   войти в голосовой канал, нажать «Показать экран», увидеть системный диалог и свою картинку у
   второго участника. Если не работает — нативный захват через ScreenCaptureKit (+12–20 ч) или
   экран только на Windows.
3. **Голос, RNNoise и секретный чат** упираются не в WebView (все нужные API на месте), а в ручную
   проверку: разрешения микрофона, звук у собеседника, 30 минут в свёрнутом окне (DESK-2).
4. **`backgroundThrottling: "disabled"`** в конфиге окна поддерживается на macOS и не поддерживается
   на Windows (там нужны флаги WebView2) — это работа DESK-2, здесь ничего не меняли.

## Ограничения этой проверки

- Оболочка запускалась в песочнице агента: WebKit не смог писать в `~/Library/WebKit` (Cocoa 513),
  поэтому сохранение cookie и `localStorage` **между запусками** приложения не проверено — только
  внутри одной сессии. В обычном запуске каталог доступен, и это надо перепроверить.
- `.dmg` в песочнице не создаётся: `hdiutil create` получает «Операция не разрешена». `.app`
  собирается, подпись и установщик — DESK-9/DESK-10.
- Снять скриншот окна не удалось (у процесса агента нет разрешения Screen Recording), поэтому
  визуальных артефактов нет: доказательства — вывод пробы и логи.
- LiveKit в локальном `.env` указывает на внешний адрес, а не на контейнер: голос в этом прогоне не
  поднимался.
