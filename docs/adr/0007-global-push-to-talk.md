# ADR-0007. Глобальный push-to-talk через системный хоткей

Дата: 2026-10-31 · Статус: принято

## Контекст

Push-to-talk в браузере работает, только пока вкладка Orbit в фокусе: клавиатуру страница видит
исключительно в активном окне. Для desktop это бессмысленно — человек уходит в игру или в редактор
и продолжает говорить. Нужна клавиша, которую слышит вся система (DESK-6, FEAT-3), с состояниями
«нажато» и «отпущено».

## Решение

1. **`tauri-plugin-global-shortcut` 2.4.1** в оболочке. Регистрация — из Rust-команды
   `set_push_to_talk`, наружу плагин не выставлен: JS-пакет в web не добавляется, права
   `global-shortcut:*` не нужны.
2. **Команда `set_push_to_talk(accelerator) -> Result<Option<String>, String>`** возвращает
   каноническую комбинацию, которую реально заняла ОС (`Shortcut::into_string()`, например
   `shift+super+Backquote`), либо `None` при снятии. Ошибка — строка: «нет модификатора» или
   «занято/не распознано».
3. **Откат при отказе.** Если новая комбинация не встала, прежняя регистрируется обратно: остаться
   без push-to-talk из-за неудачной смены клавиши хуже, чем не суметь её сменить.
4. **Комбинация обязана иметь модификатор.** Пикер в настройках хранит `KeyboardEvent.code`; голая
   клавиша в системном хоткее перехватила бы её у всех приложений — `Backquote` перестал бы
   печататься везде. Оболочка проверяет `mods.is_empty()` и отказывает, страница показывает
   подсказку «в приложении клавиша работает вместе с ⌘⇧ / Ctrl+Shift».
5. **События.** Оболочка шлёт `orbit://push-to-talk` с `{ pressed: boolean }` в окно; web слушает
   через `PlatformAdapter.pushToTalk.onChange`. Нужны права `core:event:allow-listen` и
   `core:event:allow-unlisten` — без них `listen` отклоняется ACL.
6. **Отпускание при выходе.** На `RunEvent::ExitRequested` оболочка отправляет `{ pressed: false }`:
   зажатая клавиша не должна оставить микрофон открытым после закрытия приложения.

## Последствия

- Клавиша работает в любом приложении, пока Orbit запущен (в том числе свёрнут в трей).
- **macOS перехватывает комбинацию системно** (Carbon `RegisterEventHotKey`): клавиша не доходит ни
  до одного приложения, включая сам Orbit. Поэтому подсказка в настройках и должна называть полное
  сочетание, а не одну клавишу.
- **Конфликт с другой программой на macOS не детектируется**: `RegisterEventHotKey` возвращает
  успех, даже если сочетание занято. Интерфейс не обещает «клавиша занята»; на Windows занятое
  сочетание возвращает ошибку честно.
- **На Windows у WinAPI нет события отпускания**: `global-hotkey` опрашивает `GetAsyncKeyState`
  каждые 50 мс, поэтому отпускание приходит с задержкой до 50 мс. Для микрофона это заметно, но
  приемлемо; в будущем можно подписываться на low-level hook.
- Комбинация — фиксированный префикс `CommandOrControl+Shift` плюс выбранная клавиша. Если понадобится
  произвольное сочетание, пикер должен начать хранить строку-акселератор вместо `code` — это
  отдельное изменение модели настроек, а не оболочки.
- Пока страница ждёт подтверждения регистрации, она слушает клавишу сама; если оболочка отказала,
  остаётся браузерное поведение. Push-to-talk не отваливается молча.

## Что осталось

- Ручная проверка: уйти в другое приложение, зажать ⌘⇧` — микрофон открывается, отпустить —
  закрывается; в чужом приложении `` ` `` не печатается, в Orbit печатается.
- Windows: проверить задержку отпускания, занять сочетание другой программой, окно от администратора
  в фокусе (UIPI глушит хоткей), русскую раскладку.
- Watchdog «нажато без отпущено» (блокировка экрана, переключение пользователя) — не сделано.
