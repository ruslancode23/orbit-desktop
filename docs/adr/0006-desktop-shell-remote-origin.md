# ADR-0006. Оболочка открывает удалённый origin, а не собранный фронт

Дата: 2026-10-27 · Статус: принято

## Контекст

Orbit нужен desktop для Windows и macOS (SCRUM-12, DESK-1). Web уже готов к обёртке: всё, что
трогает ОС, идёт через `PlatformAdapter` (`orbit-web/src/shared/platform`, ADR-0004), поэтому
оболочке не нужен свой фронт — достаточно окна.

Два способа дать окну приложение:

- **A. Удалённый origin.** Окно открывает `https://<домен>`, тот же адрес, что и в браузере.
  Нативные функции — через IPC, разрешённый только этому домену.
- **B. Фронт внутри бинарника.** Окно открывает `tauri://localhost`, API живёт на другом домене.

У B есть блокирующая проблема: запросы к API становятся межсайтовыми, а сессия — HttpOnly cookie
`SameSite=Lax`, которую WKWebView ещё и режет как стороннюю. Пришлось бы заводить второй способ
входа (токен в keychain + `Authorization`, WebSocket по токену), CORS и `Origin` для схем Tauri,
и мириться с расхождением версий фронта у пользователей.

Прод-домена и HTTPS пока нет (REL-2…5), поэтому релизная сборка должна получать домен снаружи.

## Решение

1. **Вариант A.** Окно открывает веб-приложение с его собственного origin. Cookie, CORS и проверка
   `Origin` у WebSocket работают ровно как в браузере: сервер об этом не знает. Web обновляется
   деплоем, без релиза desktop; собирается один фронт.
2. **Отдельный репозиторий `orbit-desktop`** (как `orbit-web` и `orbit-server`, ADR-0001): свой CI
   на Windows и macOS, свои релизы. В `orbit-web` не появляется ни `src-tauri`, ни Rust.
3. **IPC — только своим origin'ам.** `src-tauri/capabilities/main-remote.json` содержит
   `"local": false` и `remote.urls` со списком доменов: встроенная страница-заглушка и любой чужой
   сайт, открытый в этом окне, команд не получают. Список прав — минимум: сейчас там одна
   debug-команда пробы.
4. **CSP обеспечивает web, а не Tauri.** Tauri вставляет CSP в HTML собранного приложения, а
   удалённую страницу не трогает ([Tauri CSP](https://v2.tauri.app/security/csp/)), поэтому
   `app.security.csp` остаётся `null`, а строгость даёт `orbit-web`: мета-тег из
   `scripts/security-html.ts` плюс заголовки сервера (REL-16). Это же снимает вопрос про
   `'wasm-unsafe-eval'` для Olm и RNNoise — политику уже проверяют e2e-тесты web.
5. **Origin — конфигурация, а не код.** Порядок: `ORBIT_DESKTOP_URL` (рантайм, dev и QA) →
   `http://localhost:5173` в debug-сборке → `ORBIT_DESKTOP_ORIGIN` на этапе компиляции → без
   домена окно показывает локальную страницу-объяснение. Значение, которое задано, но невалидно,
   считается ошибкой, а не поводом молча открыть что-то другое.
6. **Сборка сверяет домен с allow-list.** `build.rs` падает, если `ORBIT_DESKTOP_ORIGIN` не
   упомянут в `capabilities/main-remote.json`: иначе приложение собралось бы и открылось, а
   нативные функции отвалились бы молча — это худший вид поломки.
7. **Окно создаётся в Rust** (`create: false` в `tauri.conf.json`), потому что адрес известен
   только после разрешения origin; размеры, минимумы и заголовок остаются в конфиге.
8. **`Info.plist` с `NSMicrophoneUsageDescription` и `NSCameraUsageDescription`** лежит рядом с
   `tauri.conf.json` и мержится в бандл. Без этих строк macOS завершает процесс в момент первого
   запроса микрофона, а не показывает диалог.

## Последствия

- Вход, чат и голос работают без изменений в `orbit-server`; desktop получает сессию из той же
  cookie, что и браузер.
- **Нет офлайн-оболочки.** Без сети окно показывает ошибку загрузки. Оболочка для офлайна
  появится только вместе с вариантом B.
- Удалённый контент получает доступ к IPC, поэтому каждая новая нативная функция — это новое
  разрешение в capability, а не «просто команда в Rust». Команды приложения по умолчанию доступны
  всем окнам, поэтому их список объявляется в `build.rs` (`AppManifest::commands`) и выдаётся
  capability ([Tauri capabilities](https://v2.tauri.app/security/capabilities/)).
- Debug-сборка требует запущенного `orbit-web` на 5173; `pnpm dev` в этом репозитории не поднимает
  соседний.
- Релиз без домена невозможен: до REL-3 существуют только dev-сборки.
- Изменение домена — это релиз desktop, потому что `remote.urls` вшивается в бинарь при сборке.

## Альтернативы

- **Фронт в бинарнике (B)** — отклонён на этом этапе; вернуться можно, если понадобится офлайн, и
  тогда придётся вторым способом входить в аккаунт.
- **`src-tauri` внутри `orbit-web`** — отклонён: релизы и CI у оболочки и у фронта разные, а
  Rust-сборка замедлила бы web-CI.
- **Зашитый в код домен** — отклонён: домена ещё нет, а dev-режим всё равно требует другой адрес.
